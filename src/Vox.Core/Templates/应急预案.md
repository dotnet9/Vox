# 应急预案

> 事前写好的「着火预案」：场景分级、响应流程、分场景处置手册、演练安排。

## 1. 适用范围与场景分级

| 场景 | 等级 | 触发条件 |
| --- | --- | --- |
| 核心服务不可用 | I 级 | 核心功能全量中断 |
| 数据故障 | I 级 | 数据丢失 / 损坏且备份不可用 |
| 安全事件 | II 级 | 入侵迹象 / 数据泄露嫌疑 |
| 单点组件故障 | III 级 | 有冗余可降级 |

## 2. 应急组织与职责

| 角色 | 人员 | 职责 |
| --- | --- | --- |

| 技术处置 |  | 定位与恢复 |
| 信息通报 |  | 干系人同步 |

## 3. 应急响应流程

> 发现 → 上报（时效要求）→ 定级 → 处置 → 恢复验证 → 复盘。每步写清时效与决策人。

## 4. 分场景处置手册

### 4.1 场景：核心服务不可用

1. 确认影响面（监控 + 业务确认）
2. 尝试服务重启 / 切换冗余
3. 评估数据一致性，必要时启用备份
4. 恢复后观察指标 30 分钟

### 4.2 场景：数据故障

> 优先保现场（快照留证），再走恢复；恢复后核对数据完整性。

### 4.3 场景：安全事件

> 先隔离（断网 / 停服），再取证，恢复前必须完成漏洞修复。
