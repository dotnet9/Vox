# M1 需求

状态：**核心冻结**（2026-10-23 与产品作者对齐），边缘开放项见文末。

## 定位

Vox M1 = 面向 Assets.Dotnet9 的**完整写作环境 + 存量治理台**。写作、配图、元数据、体检、同步，一个应用闭环。

- 第一目标：管理 CodeWF 站点的内容源仓库 [Assets.Dotnet9](https://github.com/dotnet9/Assets.Dotnet9)（文章 + 图片一等公民 + 站点数据）
- 第二目标（M1 之后）：扩展为通用文章管理器（仓库画像抽象，见[架构](架构.md)与[决策记录](决策记录.md) D4）
- 与 Vex（通用离线文档编辑器）完全独立，各自维护；Vox 做好了可以完全不用 Vex

## 用户与日常

用户即仓库主人本人。日常最高频动作：**写文章、改文章**；其次是历史文章治理（筛选过期/低质、补全专辑/author）、图片管理。

## 三条工作流

1. **写作入库流**（最高频）：新建文章（标题 → slug/简述/大纲骨架）→ 慢慢细化正文 → 网图/AI 图拖入即入库插引用 → 体检通过 → 提交推送，网站更新。
2. **存量治理流**：浏览全库 → 体检列出缺专辑（存量 75% 缺）、缺 author（23%）、死链、孤儿图、过期/低质线索 → 逐项或批量修复/标记 → 提交推送。
3. **多平台发布流**（M2/M3，后置）：渲染 → 复制助手逐平台粘贴 → API 直发 → 状态追踪。

## M1 功能需求

按导航页组织，P0 = M1 必须，P1 = M1 尾部。

### 写作（默认页，P0）

- 新建文章向导：输入标题 → 自动生成 slug（可改）、日期、目录与 yml 骨架；可填简述、大纲骨架（生成 md 标题脚手架）→ 跳入编辑器
- 编辑器：Markdown 源码编辑（行号、语法高亮、大文档流畅），CJK 输入无异常
- 实时预览：StreamMark 渲染；**相对路径图片必须能解析显示**（本地文件），CDN URL 图片可反向映射本地文件离线显示
- 大纲跳转：预览大纲 ↔ 源码位置双向联动
- 图片入库管线：粘贴 / 拖入 / 本地选择 / URL 下载四种来源；按文章 slug 前缀命名；落入文章年月目录；插入相对路径引用；可一键设为封面（写 yml cover + 复制为 CDN URL 形态）
- 元数据侧栏表单：title/slug/description/date/categories/albums/tags/author/draft/cover 全覆盖；改表单即改 yml

### 文章库（P0）

- 全库列表：标题、日期、分类、专辑、标签、字数、封面缩略、草稿态
- 筛选：年份 / 分类 / 专辑 / 标签 / 草稿 / 缺口组合筛选；全文搜索
- 双击进入写作页编辑态（浏览态与编辑态同页切换，不开新窗口）
- 顶部统计条：文章数、字数、图片数、体检问题数（吸收旧"概览仪表盘"价值）

### 图片库（P0）

- 缩略图网格，按年月 / 所属文章分组
- 孤儿图筛选（引用面含正文与 site 数据，避免误报）
- 操作：复制 CDN 链接 / 相对路径、在文章中查看引用、删除（走 git）
- 拖入即入库（目标目录可选，默认当前选中文章的年月）

### 体检（P0）

- 规则分组的问题列表：缺 albums、缺 author、图片死链（含扩展名配对自动修复建议）、孤儿图、slug 不合规、过期/低质线索（年份 + 字数 + 引用数）
- 每条问题可跳转到对应文章/图片；支持批量修复（专辑补全向导：按分类/标签推断建议，批量确认）
- 治理标记：文章级"重写 / 退役 / 删除"人工标记；删除走 git 可回滚，无物理删除

### 同步（P0）

- git 语义化改动列表（"改了 3 篇文章 + 2 张图"，不是文件名列表）
- 提交信息（自动生成建议）、一键提交并推送（HTTPS + PAT 默认，SSH 降级外部 git）
- 历史记录浏览

### 站点数据（P1）

- `site/categories.json`、`albums.json`、`friend-links.json`、`timelines.json` 表单化编辑（仅 zh-CN；en/ja/zh-tw 文件不在计划内，后续由作者批处理删除）

### 设置（P1）

- 仓库路径、链接策略（首选形态：相对路径 / CDN；域名 ↔ 路径映射规则）、PAT 管理、外观（Arc 强调色 / 明暗）

## 非目标（M1 明确不做）

- 国际化：仓库按纯 zh-CN 对待，不做多语言数据视图
- 不做 AI 生图：图片来源在 Vox 外部完成，Vox 只负责入库管线
- 不做自动删除：治理决策人工拍板
- 不做多平台发布（M2/M3 后置）
- 不做通用仓库支持（仓库画像抽象留到第二目标，见决策 D4）
- 与 Vex 无功能耦合、无代码依赖
