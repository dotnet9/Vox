# 架构与技术选型

状态：骨架共识（2026-10-23），实现细节在 spike 后可能微调。

## 解决方案结构

```text
Vox.slnx
├── src/
│   ├── Vox.Core   ← 纯逻辑，零 Avalonia 依赖，全部可单测
│   ├── Vox.Git    ← git 能力层，隔离原生与外部进程细节
│   └── Vox.App    ← Avalonia 桌面壳
└── tests/
    ├── Vox.Core.Tests
    └── Vox.Git.Tests
```

三项目起步，痛了再拆。不引入 Prism.DryIoc 等重量级框架，DI 用 Microsoft.Extensions.DependencyInjection。

### Vox.Core

- **中立领域模型**：`Article`、`ArticleMeta`、`ImageAsset`、`SiteData`——不含 yml/路径等仓库细节，UI 与业务只面对这些类型（决策 D4）
- **仓库画像（RepoProfile）**：CodeWF 的目录约定（`YYYY/MM/slug.md` + sidecar `slug.yml`）、元数据字段、图片映射规则，写死但隔离在此模块，为第二目标"通用文章管理器"留抽取缝
- **扫描与索引**：全库扫描建内存索引（536 篇文章 / 4200+ 图规模完全可内存承载）+ FileSystemWatcher 增量维护
- **链接策略**：相对路径 ↔ CDN URL 双形态模型、互转、首选形态配置
- **体检规则引擎**：规则可注册、可批量执行、产出结构化问题（定位 + 修复建议），输入来自索引
- **图片入库规则**：slug 前缀命名、年月目录落位、封面字段回写

### Vox.Git

- **LibGit2Sharp 为基座**：status / 暂存 / 提交 / 历史 / diff / HTTPS+PAT 推送，进程内完成
- **SSH 推送降级**：优先调用系统 PATH 中的 git（复用用户既有密钥配置），其次使用随 Vox 分发的 MinGit（Git for Windows 官方免安装精简版，含 OpenSSH，**仅 Windows 捆绑**；Linux/macOS 使用发行版包管理器安装的系统 git）
- **凭据**：PAT 存操作系统级凭据库（`ICredentialStore` 抽象：Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service，后者缺席时回退加密文件并提示），不进仓库、不上传（决策 D5）

### Vox.App

- **壳与导航**：左导航七页（见 [信息架构.md](信息架构.md)），Arc 主题（强调色 / 明暗 / 动效级别）
- **预览**：TKCode.StreamMark `MarkdownView` + `RefreshMarkdown` 增量刷新；相对路径图片解析器由 Vox 实现（StreamMark 将相对链接交给宿主）；`Theme.AtomUI` 主题包对齐 Arc 视觉
- **编辑器**：AvaloniaEdit（Vex 同款，`Avalonia.AvaloniaEdit` 12.0.0 已在 Avalonia 12.1.4 + NativeAOT 生产验证）+ TextMate 插件（与 StreamMark 同源 TextMateSharp，编辑/预览高亮一致）——TextMate 版本对齐待 spike。集成注意（Vex 踩过的坑）：AvaloniaEdit 的 Simple 主题要求宿主主题提供字体令牌，Arc 主题下需像 Vex 那样自行补齐
- **MVVM**：CommunityToolkit.Mvvm（源生成器、AOT 友好）

## 跨平台（五 RID）

目标平台：**win-x64、linux-x64、linux-arm64、osx-x64、osx-arm64**。

依赖就绪度：Arc 声明支持 Windows/macOS/Linux 桌面；StreamMark 的 RaTeX 原生库自带 win/linux/osx × x64/arm64；LibGit2Sharp 自带各 RID 的 libgit2；AvaloniaEdit 为纯托管控件。TextMateSharp（Oniguruma）的原生覆盖在 CI 中例行验证即可。

平台差异处理：

| 事项 | Windows | Linux / macOS |
| --- | --- | --- |
| 凭据存储 | 凭据管理器 | macOS 钥匙串 / Linux Secret Service；缺席回退加密文件 |
| git 降级推送 | 捆绑 MinGit | 系统 git（包管理器几乎必有），缺失则提示安装 |
| 字体 | Geist / Inter 随包分发，无系统字体依赖（全平台一致） | 同左 |

发布与安装：本地仅构建 win-x64 NativeAOT；五平台由 GitHub Actions 原生 runner 在 release tag 触发。**分发只走 GitHub Releases**（决策 D11），安装/卸载遵循各平台惯例（原型：`design/安装器-*.html` / `卸载-*.html`）：Windows 为 Arc 品牌自绘向导（捆绑 MinGit）；macOS 为标准 DMG 拖拽安装（DMG 背景图品牌位，签名 + 公证），卸载即拖入废纸篓、不内置卸载器；Linux 的 .deb / .rpm 由系统软件中心与包管理器接管，另有 AppImage 通用包。应用内「检查更新」从 Releases 下载新版本替换，不经应用商店。品牌资产 logo.svg / png / ico 在仓库根目录统一维护（决策 D12）。

## 链接策略管线

同一图片两种合法形态，映射规则：`https://img1.dotnet9.com/<路径>` ↔ 仓库文件 `<路径>`。

- 编辑期：插入**相对 md 文件目录的路径**（同年月即文件名，跨目录 `../`）；预览按文章目录为基准解析本地文件（StreamMark ImageBaseUri 随文章切换）
- 发布期：改写为 CDN URL——**改写时机待定**（开放问题 #2：若站点端能解析相对路径则可省略；否则在 git push 前由 Vox 完成改写）
- 体检：两种形态均合法，按设置的"首选形态"提示规范化，提供批量互转命令

## 性能与规模假设

- 单仓库 ≤ 数千文章、≤ 数万图片：全量内存索引 + 后台增量，无数据库（M3 的 SQLite 仅用于发布状态）
- 图片缩略图按需生成并缓存，不阻塞列表
