# 决策记录（ADR-lite）

记录关键决策的背景与理由，避免将来"当时为什么这么定"失忆。格式：背景 → 决策 → 代价/备选。

## D1 · 不做国际化（2026-10-23）

- **背景**：Assets.Dotnet9 的 site/ 下有 zh-CN/en/ja/zh-tw 四份数据，多语言文件系早期 AI 生成，无实际意义。
- **决策**：仓库按纯 zh-CN 对待；en/ja/zh-tw 文件不在 Vox 计划内，由作者后续批处理删除。
- **代价**：若未来重启多语言，站点数据模块需重开多语言视图。

## D2 · 技术底座 = TKCode.Arc + StreamMark（2026-10-23）

- **背景**：Vex 系（CodeWF.Avalonia / CodeWF.Toolkit / Semi.Avalonia / Ursa.Avalonia）是旧技术路线；Arc（AtomUI 底座）提供完整组件 + 主题 + 动效，StreamMark 提供高性能 Markdown 预览（RefreshMarkdown 增量刷新、源码偏移映射、任务复选框、NativeAOT 零警告门槛）。
- **决策**：Vox 只依赖 Arc/StreamMark/AtomUI 生态，与 Vex 技术栈完全独立。
- **代价**：两库均处 preview 期（Arc 0.3.0-preview、StreamMark 0.1.0-alpha），API 会变；Avalonia 12.1.4 被 Arc 精确锁定。

## D3 · Vox 定位"完整写作环境"，与 Vex 独立（2026-10-23）

- **背景**："VS Code 直接开仓库就能改文件，为什么要用 Vox？"
- **决策**：Vox 的价值 = VS Code 做不到的四层：图片入库管线、仓库语义视图、体检与修复、发布闭环。编辑动作与仓库知识焊在一起（改封面是点击动作，不是编辑 yml）。Vox 做好了可完全不用 Vex。
- **代价**：纯 md 源码编辑体验不追平 VS Code，不以此为设计目标。

## D4 · 仓库画像先写死 CodeWF，领域模型保持中立（2026-10-23）

- **背景**：第一目标只有一个仓库（n=1），第二目标是通用文章管理器。第一天就抽象有"凭一个样本猜错抽象形状"的风险。
- **决策**：中间路线——CodeWF 规矩（目录约定、sidecar yml、图片映射）写死但隔离在 Vox.Core 的画像模块；内部类型中立（`Article` 而非 `YmlSidecar`），yml 读写收拢独立。将来抽接口只换隔离模块，UI 与业务零改动。
- **备选**：day-1 `IRepoProfile` 接口化（推迟，等见过第二个仓库再抽）。

## D5 · git 内置，分层降级（2026-10-23）

- **背景**：站点直接读仓库，git push 即"发布"；写作流要闭环到"推完网站就更新"，且不能要求用户安装 git。
- **决策**：LibGit2Sharp 为基座（本地操作 + HTTPS+PAT 推送）；SSH 推送降级调外部 git——优先系统 PATH 已装的 git，其次随 Vox 分发的 MinGit（官方免安装精简版，含 OpenSSH，本机无需安装）。凭据存操作系统级凭据库（`ICredentialStore`：Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service，缺席回退加密文件）。
- **代价**：LibGit2Sharp 的 SSH 支持弱，故 SSH 走外部进程；MinGit 增加安装包体积（仅 Windows）。

## D6 · 图片是一等公民，链接双形态（2026-10-23）

- **背景**：仓库即图床（`img1.dotnet9.com` ↔ 仓库路径一一对应），4203 张图 vs 536 篇文章；存量 527 孤儿图、58 死链。
- **决策**：图片库独立成页；同一图片允许相对路径 / CDN URL 两种形态，映射互转；编辑期默认相对路径，发布期改写 CDN（改写时机待站点端能力确认）；体检的引用面包含 site 数据防误报。
- **代价**：链接策略配置与规范化命令需要做好，否则两种形态会越来越乱。

## D7 · 删除永远走 git（2026-10-23）

- **背景**：存量治理需要删除低质/过期文章与孤儿图。
- **决策**：删除 = git 暂存变更 → 预览 → 提交 → 推送，全程可回滚；无"确认删除？"式物理删除。
- **代价**：依赖内置 git 层的可靠性（先过 spike）。

## D8 · 存量治理：系统给线索，人工拍板（2026-10-23）

- **背景**："过期技术 / 低质文章"无法可靠自动判定。
- **决策**：体检只提供线索列表（年份、字数、引用数、缺口），作者用文章级标记（重写/退役/删除）逐篇决策；批量仅限无争议项（如扩展名配对修复、专辑补全确认）。

## D9 · MVVM = CommunityToolkit.Mvvm + MEDI（2026-10-23）

- **决策**：不引入 Prism.DryIoc/ReactiveUI（旧 README 遗留口径）；源生成器 + AOT 友好 + 依赖注入用 Microsoft.Extensions.DependencyInjection。

## D10 · 编辑器 = AvaloniaEdit + TextMate（2026-10-23，经 Vex 预验证）

- **背景**：StreamMark 是只读渲染器，明确"从不编辑源文本"；编辑器曾选型悬空。经查证 Vex 生产代码：`Avalonia.AvaloniaEdit` 12.0.0 已在 Avalonia 12.1.4 + NativeAOT（win-x64 本地发布）下稳定使用，兼容性顾虑消除；Vex 的着色走 CodeWF.Avalonia.Markdown 自研 highlighting，未用 TextMate。
- **决策**：AvaloniaEdit + TextMate 插件（与 StreamMark 同源 TextMateSharp，编辑/预览高亮一致）。集成注意：AvaloniaEdit 的 Simple 主题要求宿主提供字体令牌（Vex 的 App.axaml 有现成处理先例）。
- **剩余风险**：仅 TextMate 插件与 Arc 依赖链的 TextMateSharp 版本对齐，见 [技术验证Spike.md](技术验证Spike.md)。
