# Vox 原型与 Avalonia 实现对齐清单

> 基准：`design/Vox.html` + `design/assets/tokens.css` + `design/assets/app.css`。
> 本清单区分“代码中存在对应功能/结构”与“已通过截图证明像素一致”。后者必须在相同窗口尺寸、主题、密度和内容数据下运行应用并截图比对；静态读代码不能替代视觉验收。

## 视觉基线

| 项目 | 原型基准 | 当前实现核对 |
|---|---|---|
| 主窗口 | 1280 × 830，圆角窗口容器 | MainWindow 默认尺寸 1280 × 830；最小尺寸 1080 × 660。Avalonia 窗口外框、系统缩放与网页容器并非同一渲染环境，需截图验收 |
| 标题栏 | 42px；品牌、文件/帮助菜单、当前文件与发布状态、MCP/搜索/外观/语言、窗口按钮 | 42px 自绘标题栏与对应操作存在；已补回 MCP 快捷入口和运行状态点；需继续核对图标、间距、菜单弹层宽度与标题栏项目压缩行为 |
| 左导航 | 展开 196px、折叠 56px；七个工作区；圆角卡片 | 已有七工作区与展开/折叠；宽度 196/56。计数徽标、选中态和导航内边距需截图比对 |
| 页面基准 | 页面常规内边距 18px；暖白/浅灰背景、细边框、轻阴影 | 各页面主要容器多使用 18px；需逐页检查滚动区、页头与卡片之间的垂直节奏 |
| 字体 | Geist / Inter / Segoe UI；代码 Cascadia Code / Geist Mono；根字号 13px，密度 12/13/14px | VoxTheme 提供字号密度令牌，代码字体有回退链；需核对实际字体是否随包部署、缺字回退和各页硬编码字号 |
| Arc / Pixel | 外观弹层有 Arc / Pixel 两种风格 | 已新增持久化风格选择；Pixel 将 VoxStyles 中已接入令牌的控件圆角置零。代码中直接设置的个别圆角与 Arc 控件内部模板尚未完全覆盖，列为视觉回归项 |

## Markdown 编辑器与阅读体验

| 能力 | 原型表现 | 当前实现 | 待验证/差距 |
|---|---|---|---|
| Markdown 源码 | 独立源码卡、等宽字体、行号/语法高亮、滚动与编辑 | CodeWF MarkdownEditorView，编辑变更驱动预览与自动保存；Geist Mono 优先、11.5px 基准字号、1.95 行高、12px 上下留白、44px 行号区，语法色由 VoxTheme 提供 | 已将字号/行高/上下留白/行号区和语义调色板接入原型令牌；仍需截图核对字形、缩进、选区/光标、滚动条和各语法 token 的精确色值；行号列宽 44px、字号 11px、右内边距 12px 已显式对齐原型；行号字形仍由 CodeWF 控件内部使用 Cascadia Mono，与原型 Geist Mono 的字形差异需在目标 Windows 环境截图核验；主题切换时会触发编辑器重算配色 |
| 实时预览 | Markdown 正文排版，标题/段落/列表/引用/代码/表格/图片 | CodeWF MarkdownViewer，绑定 Vox 语义画刷与增量渲染；正文 max-width 720px 居中，标题/段落/代码块字号和段距按原型设置 | 需逐元素核对标题比例、正文宽度 720px、段间距、代码块、引用背景、表格、图片边距；检查暗色与主题切换 |
| 阅读样式 | 简约等排版主题选择；字号紧凑/标准/宽松 | MarkdownTheme + MarkdownSize 持久化，预览控件应用 TypographyTheme / ParagraphFontSize / ParagraphLineHeight | 排版菜单已存在；需逐个主题核对实际字体、标题层级、正文行宽、行高和代码/引用细节 |

## 已发现并已补齐

- 外观弹层缺少原型中的 Arc / Pixel 风格选项：新增 `VoxSettings.UiStyle`、持久化切换和四语标签。
- Pixel 模式已接入 Vox 自有控件圆角令牌（按钮、输入框、分段、导航、菜单、弹层、卡片、缩略图等）；不覆盖 Arc 控件模板。尚有直接写死圆角的少数自绘元素待逐项纳入，不能将 Pixel 视为完整 CSS 选择器移植。
- 写作页大纲面板默认宽度已从 292px 调整为原型 300px。
- Markdown 源码编辑器已接入 Vox 明暗/强调色调色板，并按原型调整字号、行距、上下留白和行号区宽度；主窗口现在先应用主题资源再构造页面，避免首屏落入默认蓝色配色。
- Arc Select/Input 已替换文章/图片/发布等页面的部分自定义筛选和搜索控件。
- 文章库与图片库统计卡均为桌面四列、窄窗口两列；图片缩略图按可用宽度动态计算列数与卡片宽度。

## 下一轮视觉验收顺序

1. 在 1280 × 830、100% 缩放、Arc 风格、标准密度、亮色主题下，分别截取七个工作区。
2. 写作页再分别截取源码、分屏、预览、导图四态；预览逐一截取排版主题，导图逐一截取布局与样式。
3. 对每张截图与原型同视口截图做叠图/差异图；优先修正大区块边界、宽高、内外边距，再修字体、行高、图标、边框和阴影。
4. 再覆盖 Pixel、紧凑/宽松、暗色和不同窗口宽度；检查控件焦点、悬停、禁用、空状态、弹层和滚动状态。
5. 每轮修改后运行 `dotnet restore`、`dotnet build` 与相关测试；如果环境无法运行桌面 UI，则明确记录“未做截图验收”，不能把静态尺寸核对说成像素级通过。
